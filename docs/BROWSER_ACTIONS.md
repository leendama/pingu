# Reviewed browser actions

Browser actions are disabled unless `PINGU_BROWSER_ALLOWED_ORIGINS` contains a comma-separated list of explicit HTTPS origins, for example `https://forms.example.com`. Install the browser with `npx playwright install chromium`. No personal browser session, credentials, or cookies are imported. Existing service APIs remain preferable when available.

This first adapter supports native same-origin POST forms using URL-encoded text fields and a single submit button. It disables page JavaScript and service workers, uses an isolated non-persistent browser, blocks non-allowlisted requests, and permits only one POST with the exact reviewed endpoint and serialized fields. It does not support sign-in, JavaScript applications, uploads, selects, checkboxes, multiple submit buttons, or cross-origin forms. A GET must be read-only according to the enabled site's contract; generic browser code cannot prove that a badly designed site's GET has no side effects.

The owner can ask to inspect a form or prepare specified field values. Preparing sends a deterministic review containing the page, destination, button and values. Hidden fixed fields are included; form tokens are represented as unchanged rather than exposed. Only after successful review delivery does the record become approvable. Reply `confirm browser <id>`, `cancel browser <id>`, or `check browser <id>`. These commands are parsed only for a verified owner in a direct message. The model has no submission tool, and an unqualified “yes” cannot authorize a browser write.

Approval pins a hash of the entire payload, including the form fingerprint. A transaction claims it once; duplicate prepared versions cannot both submit. A separate action identity excludes temporary form tokens, so a refreshed token cannot make an uncertain submission retryable. The browser reloads the form and validates its fingerprint before filling. Changed fields, hidden state, destination, title or button invalidate the action before submission. Reviews expire after 15 minutes. Dynamic CSRF values may require a site-specific session adapter; the generic adapter refuses a changed token.

A received HTTP response is saved as submission evidence, not business-outcome verification. Errors after submission may have begun, and interrupted executions, are held as `unknown`. There is no automatic repeat. `check browser <id>` exposes the saved status and response so the owner can verify with the site. Automatic recovery of a lost receipt requires a site-specific read-only lookup with a unique submission identifier; this generic adapter does not invent that capability. Live sites should stay disabled until their supported form and receipt semantics are evaluated.

Records live in `PHOTON_DATA_DIR/browser-actions.sqlite`, are private to the owner chat, and are cleared by forgetting that chat, owner removal or full data reset. No remote forms are submitted by tests. The implementation follows Playwright's [isolated contexts and request interception](https://playwright.dev/docs/api/class-browsercontext) and [locator actions](https://playwright.dev/docs/locators).
